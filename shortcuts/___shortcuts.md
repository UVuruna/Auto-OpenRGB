# shortcuts/

One folder per shortcut SET, named after the set (e.g. `Rainbow/`,
`Main Colors/`), each holding one VBS per key the user picked:

```
📁 shortcuts/
  📁 Rainbow/
    🔧 F1.vbs … F12.vbs     ← runs the Resolver with --shortcut "Rainbow:F1"
```

The user's flow (see [Shortcuts Tab](../gui/__about/shortcuts_tab.md)): name
the set → pick selector → pick ANY keys → bind each key to a COLOR or a
whole PRESET → "Create shortcut files". A preset binding switches the
active preset on press (see [Actions](../core/__about/actions.md)). Normal
selectors are then registered automatically by the
[Hotkey Daemon](../__about/hotkey_daemon.md); for **hypershift** sets the
GUI opens this folder plus Razer Synapse with a linking guide — each key's
file is linked in Synapse ONCE, and re-mapping colors later is a pure
config change (the files never need re-linking).

A slot whose set or key was removed is a quiet no-op. Folders are
regenerated by the GUI or `python resolver.py --write-slots` — see
[Resolver (flow)](../__flow/resolver.md). Folders of deleted sets are
cleaned up. Generated files get no individual docs (project convention,
Trivial by nature — pure generated VBS wrappers); the per-set folders
themselves are gitignored (`shortcuts/*/` — they embed the local Python
path), only this doc is tracked.

## Connections

### Uses
- [Resolver](../__about/resolver.md) — `write_set_folder` generates every file here

### Used by
- Razer Synapse (hypershift sets, LAUNCH bindings) and the
  [Hotkey Daemon](../__about/hotkey_daemon.md) (normal selectors, via `RegisterHotKey`)
